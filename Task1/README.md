# Задание 1. Проектируем шаги Saga

## Таблица-реестр транзакций Saga-оркестрации

| Транзакция        | Описание                                                                                                                                                                                                      | Тип            | Компенсация      |
| ----------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- | -------------- | ---------------- |
| `CREATE_PAYMENT`  | Создать запись платежа в Payment Service                                                                                                                                                                      | компенсируемая | `CANCEL_PAYMENT` |
| `HOLD_FUNDS`      | Заблокировать сумму на счёте клиента (prepare, без фиксации)                                                                                                                                                  | компенсируемая | `RELEASE_HOLD`   |
| `CHECK_FRAUD`     | Проверить транзакцию в FraudCheck (разрешение / запрет / ручная проверка). Идемпотентность, retry, кэш Redis, cut-off. Нет ответа до cut-off или решения оператора за 20 минут - платёж считается разрешённым | повторяемая    | -                |
| `TRANSFER_FUNDS`  | Списать захолдированные средства и перевести контрагенту после всех проверок. Точка невозврата. Возврат после перевода - отдельный процесс                                                                    | необратимая    | -                |
| `NOTIFY_CLIENT`   | Уведомить клиента о статусе операции. На ветке отказа выполняется после `CANCEL_PAYMENT`                                                                                                                      | повторяемая    | -                |
| `NOTIFY_SECURITY` | Уведомить службу безопасности при подозрительной операции. На ветке отказа выполняется после `CANCEL_PAYMENT`                                                                                                 | повторяемая    | -                |
| `RELEASE_HOLD`    | Снять блокировку средств на счёте клиента. При запрете антифрода или сбое до точки невозврата выполняется первым                                                                                              | повторяемая    | -                |
| `CANCEL_PAYMENT`  | Отменить платёж и зафиксировать итоговый статус. Выполняется после `RELEASE_HOLD`, затем идут уведомления                                                                                                     | повторяемая    | -                |
