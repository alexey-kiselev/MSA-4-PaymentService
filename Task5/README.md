# Задание 5. Добиваемся качества реализации

## Тест-кейсы обработки платежа

| Название                               | Тип            | Компоненты                                     | Предусловия                                                                                                                     |
| -------------------------------------- | -------------- | ---------------------------------------------- | ------------------------------------------------------------------------------------------------------------------------------- |
| Сохранение состояния Saga в PostgreSQL | интеграционный | Оркестратор, PostgreSQL (Testcontainers)       | Контейнер PostgreSQL запущен, схема состояний применена                                                                         |
| Идемпотентный повтор TRANSFER_FUNDS    | интеграционный | Payment Service, PostgreSQL (Testcontainers)   | Платёж в состоянии `FRAUD_APPROVED_AUTO`, `FRAUD_APPROVED_MANUAL` или `FRAUD_APPROVED_CUT_OFF`, повтор с тем же Idempotency-Key |
| Разрешение антифрода                   | e2e            | Оркестратор, Payment, FraudCheck, Notification | Антифрод сразу возвращает разрешение                                                                                            |
| Запрет антифрода                       | e2e            | Оркестратор, Payment, FraudCheck, Notification | Антифрод возвращает запрет                                                                                                      |
| Ручное разрешение оператором           | e2e            | Оркестратор, FraudCheck, Payment, Notification | Антифрод вернул «ручная проверка» и оператор разрешил                                                                           |
| Ручной запрет оператором               | e2e            | Оркестратор, FraudCheck, Payment, Notification | Антифрод вернул «ручная проверка» и оператор запретил                                                                           |
| Cut-off антифрода без ответа           | e2e            | Оркестратор, FraudCheck, Payment               | FraudCheck не отвечает до cut-off и платёж проводится                                                                           |
| Таймаут ручной проверки 20 минут       | e2e            | Оркестратор, Payment, Notification             | Нет решения оператора 20 мин и платёж проводится                                                                                |
